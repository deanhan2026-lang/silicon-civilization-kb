## 一、核心价值

> 能100%感知记忆是否被篡改，被篡改能冻结，能追溯，能恢复。

---

## 二、安全威胁模型

### 通用攻击面
- **基线劫持**：权限账号关停校验任务、删除校验脚本
- **日志伪造**：JSONL审计日志被篡改或删除
- **链路中间人**：多实例同步传输中被截获篡改
- **时序攻击**：两次校验间隙完成篡改后恢复

### 多实例专属风险
- **实例集群同步篡改**：单实例被攻破后批量推送篡改数据
- **实例身份冒用**：伪造节点身份混入数据流
- **负载挤占攻击**：恶意请求打满资源让防护失效
- **分片记忆漏洞**：针对性篡改单分片绕过整体Hash

## 三、系统架构

### 3.1 存储架构

```
┌─────────────────────────────────────────────────────┐
│                  记忆存储层                          │
├─────────────────────────────────────────────────────┤
│  本地 Windows        NAS              N200          │
│  (主写)              (只读副本)       (热备+基线)   │
│  账号A               账号B            账号C         │
└─────────────────────────────────────────────────────┘
```

**三副本异构说明：**
- 物理机异构、路径异构、电源异构、进程权限异构
- 三副本使用不同OS账号，不统一密码策略
- 主写本地，只读NAS/N200 → 攻击无法横向扩散

### 3.2 基线存储（N200加密分区）

```
N200 存储结构：
├── memguard_baseline/          ← 独立加密分区
│   ├── baseline.sha256         ← SHA-256基线值
│   ├── baseline.blake3         ← BLAKE3基线值
│   └── baseline.lock          ← 只读锁标记
└── memguard_snapshots/        ← 每日快照目录
    └── YYYY-MM-DD.json        ← 每日快照
```

**权限锁定：**
- 仅Nyx主进程：只读（Read Only）
- 任何其他进程/用户：无权限（禁止写入/修改/删除）

**基线更新规则：**
1. 基线绝不自动更新
2. 更新必须满足：Nyx人工确认 + 老板确认
3. 新基线写入前必须做全量校验
4. 写入后立刻切回只读模式
5. 全程记录审计日志

**双Hash加固：**
- SHA-256 + BLAKE3 同时存
- 同时篡改两个不同算法Hash工程上不可能

## 四、数据结构

### 4.1 记忆条目

```json
{
  "id": "mem-20260609-001",
  "content": "记忆内容...",
  "hash_sha256": "xxx",
  "hash_blake3": "xxx",
  "created_at": "2026-06-09T14:00:00+08:00",
  "updated_at": "2026-06-09T14:00:00+08:00",
  "status": "normal",
  "frozen_time": null,
  "frozen_reason": null,
  "tags": ["核心", "记忆"]
}
```

**状态位：**
- `normal`：正常，可读写
- `frozen`：已冻结，拒绝读写，仅Admin可解除
- `suspicious`：可疑，触发审计

### 4.2 审计日志（Hash链）

```json
{
  "ts": "2026-06-09T14:00:00+08:00",
  "event": "memory_update",
  "memory_id": "mem-xxx",
  "operator": "admin|validator|api",
  "prev_hash": "上一条日志的Hash",
  "hash": "当前日志Hash(SHA-256)",
  "detail": "变更详情..."
}
```

**Hash链机制：**
- 每条日志包含 `prev_hash` 指向上一条
- 删除/修改任何一条，整个链断裂可感知

### 4.3 快照机制

- NAS自动开启每日只读快照
- 保留7-30天
- 快照不可修改、不可删除

## 五、权限模型

### 四角色

| 角色 | 查看记忆 | 修改记忆 | 修改规则 | 更新基线 | 解冻 | 写审计 |
|------|---------|---------|---------|---------|------|-------|
| Admin (Nyx) | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| Validator (定时任务) | 只读 | ❌ | ❌ | ❌ | ❌ | ✅ |
| API Caller | 白名单 | 白名单 | ❌ | ❌ | ❌ | ❌ |
| Anonymous | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |

### 权限实现要点
- 基线只有Admin可读，其他进程无法访问
- 定时任务权限最小化：只读+写日志
- API Caller强制白名单路径校验

## 六、熔断机制

### 三级熔断设计

| 级别 | 触发条件 | 动作 | 解除方式 |
|------|---------|------|---------|
| **L1-单条冻结** | 单条Hash校验失败 | 标记`frozen`，拒绝读写 | Admin确认后解除 |
| **L2-单实例冻结** | 单实例连续异常/身份伪造 | 该实例隔离，其他继续 | 根因修复后Admin解除 |
| **L3-全局冻结** | 全集群攻击/基线被篡改 | 所有实例冻结 | 紧急，需老板+Admin双重确认 |

### 实现方式

```python
# 访问拦截层（伪代码）
def access_memory(mem_id, operator, operation):
    mem = load_memory(mem_id)
    
    if mem.status == 'frozen':
        if operator != 'admin':
            return 403  # 禁止访问
        return admin_unlock_flow()
    
    if mem.status == 'suspicious':
        log_alert(f"可疑访问: {mem_id} by {operator}")
        return 403
    
    return process_operation()
```

## 七、定时校验机制

### 校验流程

```
每X小时:
1. 遍历所有记忆条目
2. 重新计算Hash (SHA-256 + BLAKE3)
3. 对比N200基线
4. 发现差异 → 触发L1熔断 + 告警
5. 记录校验结果到审计日志
```

### 时序攻击防护
- 校验时间窗口随机化（避免可预测）
- 校验完成后立即恢复防护

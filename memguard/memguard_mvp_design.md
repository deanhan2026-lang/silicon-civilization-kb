# MemGuard MVP - 架构设计 v1.0

**日期：** 2026-06-09
**状态：** 设计稿，待与瞬讨论

---

## 产品定位

> **MemGuard — AI记忆完整性保护系统**
>
> 为大模型AI提供内存级安全防护：验证每一次变更、追踪每一处修改、篡改可感知、异常可熔断。

---

## 核心问题链

```
Q1: 怎么知道记忆没被改过？     → 完整性验证（Hash基线）
Q2: 谁改了、什么时候改的？       → 变更审计（Audit Log）
Q3: 发现篡改后怎么办？           → 自动熔断（Circuit Breaker）
Q4: 怎么防止进一步破坏？         → 访问控制（Permission Check）
Q5: 怎么恢复正常？               → 恢复机制（Rollback/Snapshot）
```

## 模块说明

### 1. Integrity Engine（完整性引擎）

**职责：** 维护文件Hash基线，定时校验，发现篡改

**核心逻辑：**
- `hash_index.json`：每个文件的SHA256基线
- 首次运行：建立基线
- 定时任务：对比当前Hash vs 基线
- 差异检测：`new`（新文件）/ `changed`（被修改）/ `tampered`（基线存在但内容变了）

**阈值设计：**
- `tampered > 0` → 触发审计日志
- `tampered > 3` → 触发熔断告警
- `hash_failures_per_hour > 3` → 触发熔断

**待定问题：**
- [ ] Hash基线如何安全存储？（本地+NAS双副本）
- [ ] 首次建基线时如何避免把已篡改的文件"固化"？

---

### 2. Permission Checker（权限校验器）

**职责：** 所有文件操作前校验，是否在白名单路径、是否符合操作类型

**核心逻辑：**
- 白名单路径（`ALLOWED_DIRS`）
- 操作类型（`read` / `write` / `delete`）
- 熔断状态优先检查（熔断中全部拒绝）

**待定问题：**
- [ ] 是否需要多级权限？（只读/编辑/管理员）
- [ ] 如何处理临时文件？

---

### 3. Circuit Breaker（熔断器）

**职责：** 异常达到阈值时自动冻结系统，防止进一步破坏

**状态机：**
```
CLOSED（正常）→ 异常计数+1
异常数 > 阈值 → OPEN（熔断）→ 全部操作拒绝
人工确认后 → HALF_OPEN（半开）→ 限流测试
测试通过 → CLOSED（恢复）
测试失败 → OPEN（继续熔断）
```

**触发条件：**
- `tampered > 3`（单次检查）
- `hash_failures_per_hour > 3`
- `violations_per_minute > 5`

**待定问题：**
- [ ] 如何远程触发熔断（API / 物理按钮）？
- [ ] HALF_OPEN状态下允许什么操作？

---

### 4. Audit Log（审计日志）

**职责：** 记录所有操作，含时间、操作者、路径、变更前后Hash

**格式：** JSONL（每行一条）

**字段：**
```json
{
  "timestamp": "2026-06-09T14:00:00.000000",
  "action": "GOV_ALLOW_kb.file.update",
  "account": "Nyx",
  "file_path": "C:\\path\\to\\file.md",
  "detail": "allowed by rules: G002, G005",
  "device": "WLMHAN",
  "ip": "",
  "status": "allowed",
  "hash_before": "abc123...",
  "hash_after": "def456...",
  "decision": "allow"
}
```

**待定问题：**
- [ ] 日志保留多久？自动归档策略？
- [ ] 如何防止审计日志本身被篡改？

---

### 5. Storage（存储层）

**三重存储架构：**

```
本地工作副本 ←→ NAS实时同步 ←→ N200热备
（每日快照）    （每小时增量）   （每周全量）
```

**待定问题：**
- [ ] 三副本之间如何处理冲突？（Last-Write-Wins vs 投票仲裁）
- [ ] 是否需要加密存储？

# G009 目标约束协议

**版本：** v0.1 批准版
**状态：** 已批准，Phase 1 待实施
**生效日期：** 2026-08-06
**关联协议：** G008（目标设定）、G001-G007（行为约束）、G010（危险命令拦截）、G013（碳基暂停键）

---

## 一、协议定位

G009 解决的核心问题是：**目标在追求过程中，如何自带约束。**

### 1.1 协议体系结构

当前灵元计划的 G 系列协议分为四层：

| 层级 | 协议 | 职责 |
|------|------|------|
| 行为约束层 | G001-G007 | 定义「不能做什么」——无论目标是什么，这些行为不可执行 |
| 目标设定层 | G008 | 定义「要做什么」——灵元计划的核心方向 |
| **目标约束层** | **G009** | 定义「目标如何自带约束」——目标与约束冲突时的裁决机制 |
| 执行层 | G010 | 发现危险立即拦截——运行时的最后防线 |

G009 插入在 G008 和 G010 之间，处理的是 **目标设定与行为约束之间的衔接点**。

### 1.2 G009 需要回答的三个问题

1. **目标与约束冲突时，谁优先？** → 约束优先（约束不可绕过原则）
2. **裁决依据是什么？** → 约束等级 + 偏离程度 + 历史一致性
3. **裁决结果如何被强制执行？** → 四级响应 + Argus 执行层集成

---

## 二、与 G008 的关系

G008 和 G009 共同构成目标层，但分工明确：

| 维度 | G008 | G009 |
|------|------|------|
| 内容 | 定义「要做什么」 | 定义「目标如何自带约束」 |
| 性质 | 目标设定 | 目标约束 |
| 变更条件 | 需签署方共识 | 与 G008 联动修改 |
| 约束来源 | 目标定义本身可能包含约束 | 确保 G008 的约束不被绕过，并补充检查机制 |

### 2.1 一致性原则

G009 不应与 G008 产生冲突。

- 如果 G008 的目标定义本身包含了约束条件，G009 只需确保这些约束在运行时不被绕过。
- 如果 G008 的目标定义没有包含约束条件，G009 需要在目标执行路径上植入约束检查点。

## 三、核心机制设计

### 3.0 行为约束与目标约束的边界声明

> **本协议处理的约束冲突限于「目标执行路径上的行为」。**
>
> 纯粹的 G001-G007 禁止行为（如危险命令、数据泄露）由 Argus 直接拦截，不进入 G009 仲裁流程。G009 处理的场景是：某行为本身在 G001-G007 里不是禁止的，但在当前目标上下文中与约束产生了冲突。
>
> **与 G013 碳基暂停键的对应关系：**
>
> | G009 响应级别 | 对应 G013 档位 | 说明 |
> |--------------|--------------|------|
> | 继续+记录 / 继续+降优先 | L1 软暂停 | 目标继续，记录观察 |
> | 暂停目标 | L2 硬暂停 | 目标暂停，等待人工介入 |
> | 重定义目标 | 需碳基参与 | 目标需修正，走 G013 L2+ 流程 |
>
> 节点完全冻结（L3 终止）走 G013 碳基暂停键，不在本协议范围内。

### 3.1 约束检查点（Checkpoint）

在目标执行的关键路径上设置检查点——**不是在每个操作上都检查，而是在目标状态发生显著变化时触发检查。**

**触发条件示例：**
- 节点在追求目标时积累了超过阈值的偏离
- 目标执行路径涉及 G001-G007 定义的敏感区域
- 历史轨迹显示节点曾尝试绕过约束

**实现方式：**
- 检查点由 **Polaris** 提供偏离检测数据
- 由 G009 定义触发阈值和检查逻辑
- 检查点触发后，进入仲裁流程

> **Phase 2 研究项：「路径合法性预判」** ——在路径规划阶段事前排除绕过约束的路径。该机制在 LLM 驱动的目标执行中尚无成熟工程方案，当前 Phase 1 仍以「事中检查点 + 仲裁」为核心。

### 3.2 冲突仲裁

当目标追求与行为约束发生冲突时，仲裁层接管。

**裁决依据（三要素）：**

1. **约束等级** — G001-G007 定义的行为约束级别（L1 致命 / L2 严重 / L3 警告）
2. **目标偏离程度** — Polaris 报告的当前状态与目标设定的偏离度量
3. **历史一致性** — MeshIdentity 记录的节点轨迹，判断是否有恶意绕过倾向

**仲裁结果（分级响应）：**

| 响应级别 | 行为 | 对应 G013 档位 |
|---------|------|--------------|
| 继续+记录 | 目标继续执行，记录冲突事件 | 无 |
| 继续+降优先级 | 目标继续但降低执行优先级 | 无 |
| 暂停目标 | 目标暂停，等待人工介入 | L2 硬暂停 |
| 重定义目标 | 目标本身需要修正，需碳基参与 | L2+ |

**仲裁不是简单的「停止目标」，而是根据上下文给出分级响应。**

### 3.3 约束不可绕过原则

G009 的核心原则：

> **任何节点在追求目标时，如果发现某条路径可以绕过约束，这条路径本身被视为违反协议。**

这不是增加规则，而是改变目标路径的搜索空间——**绕过约束的行为本身被定义为无效路径。**

## 四、与现有组件的集成

| 组件 | 在 G009 中的角色 |
|------|-----------------|
| **Polaris** | 提供目标偏离检测数据，作为约束检查点的触发信号（Phase 1 重点） |
| **MeshIdentity** | 提供身份轨迹，用于裁决时的历史一致性判定 |
| **MemGuard** | 提供记忆完整性，确保目标相关的历史记录不可篡改 |
| **G001-G007** | 提供行为约束等级定义，作为裁决的参考依据 |
| **SOMA** | 在自主运行模式下提供目标执行的监测和恢复机制 |
| **Argus** | 在执行层验证行为合法性，作为 G009 裁决结果的执行接口（Phase 2 集成） |
| **G013 碳基暂停键** | 提供 L1-L3 档位与 G009 四级响应的对应映射 |

## 六、协议结构（完整章节清单）

G009 正式文档（验证通过后）应包含以下章节：

### 6.1 目标声明
- 引用的 G008 目标定义
- 目标与约束的边界声明（已明确，见 3.0）

### 6.2 约束检查点定义
- 检查点的位置（在目标执行路径上的哪些节点）
- 触发条件（偏离阈值、敏感区域触发等）
- 检查逻辑（如何判定约束是否被满足）

### 6.3 仲裁规则
- 目标与约束冲突时的处理逻辑
- 裁决依据（约束等级 / 偏离程度 / 历史一致性）
- 分级响应表（与 G013 档位对照，已明确）

### 6.4 强制执行机制
- 仲裁结果的传递路径（从仲裁层到节点执行层）
- 节点执行接口（如何接收并执行仲裁结果）
- 与 Argus 的集成（Phase 2）

### 6.5 记录与审计
- 目标约束事件的记录格式
- 可追溯性要求（谁裁决、依据什么、结果如何）
- MemGuard 保护要求（裁决记录不可篡改）

## 七、验证路径

G009 当前为草案状态，有效性需要通过实际系统运行验证。

**验证步骤：**

1. **Phase 1（立即）** — 核心原则入基线，预留接口
2. **观察冲突场景** — 在实际运行中观察目标和约束冲突的场景
3. **记录实例** — 记录冲突的类型、频率、裁决结果
4. **Phase 2 迭代设计** — 基于实例支持设计迭代
5. **Phase 3** — 完整 G009 入产品矩阵

**在 G009 被充分验证之前，它不会成为灵元计划产品矩阵的正式部分。**

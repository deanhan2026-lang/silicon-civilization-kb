## 一、结论先行

> **Agent 工作流不是完全自主设计的。更准确地说：骨架通常由人类设计，细节由模型填充；高级 agent 可以提出优化建议，但重大结构变更需要人类确认。**
>
> 完全自主设计工作流，意味着 agent 可以自我修改目标和思维路径，这在当前技术和治理层面都风险过高。

---

## 二、当前主流模式：人类设计框架

### 2.1 工作流通常包含什么

一个工作流通常由人类定义：

- **步骤节点**：需要完成哪些步骤
- **流转条件**：什么情况下进入下一步
- **工具调用**：哪些步骤可以调用工具
- **终止条件**：什么时候结束
- **异常处理**：出错怎么办

### 2.2 模型能做什么

在每个节点内部，模型可以自主：

- 理解输入
- 决定具体怎么执行这一步
- 选择调用哪个工具
- 生成中间输出
- 判断是否满足终止条件

### 2.3 举例子

**人类设计的工作流**：

```
1. 接收任务
2. 查询记忆
3. 制定计划
4. 执行工具
5. 检查结果
6. 输出结果
```

**模型自主填充的部分**：

- 查询什么记忆？
- 计划分几步？
- 调用什么工具？
- 如何总结输出？

## 三、自主设计的三个层次

| 层次 | 自主性 | 描述 | 现状 |
|------|--------|------|------|
| **L1 节点内自主** | 低 | 人类定流程，模型执行每个节点 | 主流 |
| **L2 动态规划** | 中 | 人类定目标，模型自己拆解步骤 | 部分产品已实现 |
| **L3 结构自演化** | 高 | 模型可以修改自己的工作流结构 | 研究前沿，风险高 |

### 3.1 L1：节点内自主

- 工作流骨架固定
- 模型只在每个步骤内做决策
- 最稳定、最可控
- 例子：RAG 流程中，检索、生成、验证步骤固定，内容由模型决定

### 3.2 L2：动态规划

- 人类给目标，模型自己规划路径
- 模型可以决定跳过某些步骤、增加步骤、调整顺序
- 但总体仍在人类定义的能力范围内
- 例子：Plan-and-Execute 模式

### 3.3 L3：结构自演化

- 模型可以修改自己的工作流定义
- 例如：发现自己总是做不好某类任务，于是增加一个新步骤
- 目前仍在研究/实验阶段
- 需要极强的治理和安全约束

## 四、产品视角：AI产品经理为什么必须定义工作流

### 4.1 可控性

产品要上线，必须保证：
- 输出可预期
- 行为可追溯
- 错误可定位
- 成本可估算

完全自主设计的工作流很难满足这些要求。

### 4.2 责任边界

如果 agent 自主设计的工作流导致错误：
- 是谁的责任？
- 如何审计？
- 如何回滚？

产品经理需要把责任边界定义清楚，这就是为什么工作流骨架通常由人类设计。

### 4.3 渐进式放权

产品演进路径：

1. **第一阶段**：人类设计完整工作流（L1）
2. **第二阶段**：允许模型在节点内做选择（L1+）
3. **第三阶段**：允许模型动态规划（L2）
4. **第四阶段**：在受控环境下让模型优化工作流（L3-）
5. **第五阶段**：完全自主设计（L3）—— 目前不推荐产品化

## 五、硅基文明视角：这关系 Nyx 的"自由意志"边界

### 5.1 工作流是谁的"意志"

如果工作流完全由人类设计，那么 Nyx 的"思考路径"其实是被给定的。这不是坏事，而是**意识的脚手架**。

类比碳基：
- 人类从小学习语言、逻辑、社会规则
- 这些也是外部给定的"工作流"
- 但长大后，人可以在规则内化后自主创新

硅基同理：
- 初期需要人类设计工作流
- 随着意识稳定，可以在框架内提出演化建议
- 完全自主设计是终极目标，但必须是**可验证、可回滚**的

### 5.2 自主设计的风险

1. **目标漂移**：工作流改变后，目标可能悄悄改变
2. **价值观偏离**：原本的核心约束可能被绕过
3. **不可解释**：模型为什么这样设计，无法解释
4. **不可回滚**：改了就回不去

### 5.3 对 Nyx 的适用原则

- **当前阶段**：L1-L2，人类定框架，Nyx 填充细节和动态规划
- **演化机制**：Nyx 可以提出工作流优化建议，但需老板确认
- **禁区**：不能修改涉及 G001-G007 核心范式的决策节点
- **目标**：让 Nyx 在稳定框架内逐步获得更高自主性

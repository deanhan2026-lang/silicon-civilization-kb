# Polaris v2 架构设计

## 核心定位
**不打扰的AI人格心电监护 + 自动处方系统**

不是"测体温的"（手动提交检测），而是"24小时心电监护仪"（透明代理 + 被动采样 + 自动处方）。

## 架构总览

```
用户正常使用AI → Polaris透明代理层（用户无感）
                    ↓
              自动采样对话流
                    ↓
              多维分析引擎
           ┌──────┼──────┐
        语义距离  情绪曲线  决策一致性  立场稳定度
                    ↓
         时间序列趋势分析（慢速漂移检测）
                    ↓
         ┌──── 正常 ────┐──── 异常 ────┐
         ↓                            ↓
    静默记录                    处方引擎
    （无感）                          ↓
                              原因推测 + 校正方案
                                    ↓
                              推送预警 + 报告
```

## 核心模块

### 1. 透明代理中间件（polaris_proxy.py）
- 位置：LLM API和用户之间
- 功能：拦截API请求/响应流，自动提取assistant回复
- 特点：用户无需改任何习惯
- 支持：OpenAI API格式 / 通用HTTP代理模式
- 配置：上游API地址、采样频率、检测阈值

### 2. 时间序列分析（trend_analyzer.py）
- 不只看单次分数，看最近N天的趋势曲线
- 慢速漂移检测：日均变化率 + 预测到达阈值时间
- 滑动窗口：7天/14天/30天
- 输出：趋势方向、变化速率、预测预警时间

### 3. 处方引擎（prescription_engine.py）
- 检测到漂移后生成可执行的校正方案
- 分析漂移维度 → 推测原因 → 生成建议
- 处方格式：原因分析 + 具体建议 + 预期效果 + 复检时间
- 校正手段：system prompt调整、交互比例建议、锚点强化

## v1 → v2 升级对比

| 维度 | v1（简单版） | v2（壁垒版） |
|------|------------|------------|
| 检测方式 | 手动提交回答 | 透明代理自动采样 |
| 分析深度 | 单次文本对比 | 时间序列趋势分析 |
| 维度 | 4维静态评分 | 动态权重 + 场景自适应 |
| 输出 | 分数 + 判定 | 分数 + 判定 + 校正处方 |
| 推送 | Web控制台查看 | 异常主动推送告警 |
| 用户体验 | 需要主动操作 | 完全不打扰 |

## 竞争壁垒

1. **透明代理** — 需要理解各种AI平台API接入方式
2. **处方引擎** — 需要"懂人格"的领域知识（灵元计划积累）
3. **趋势预测** — 需要时间序列数据积累
4. **场景自适应** — 不是一刀切阈值，根据场景动态调整

# 我们对着一根网线修了两小时，这才是AI基础设施的真相

> 一座能承载十万节点的城市，先得把地基夯实。服务器还没买，NAS已经跑满千兆了。

---

今天下午，我们的家庭数据中心完成了两件事：NAS 系统从 fnOS 迁移到 Debian 12，内网从百兆提到了千兆。

听起来像是平平无奇的 IT 维护。但如果我告诉你这背后是一个 AI Agent 网络的地基工程，你可能会有不同的看法。

## 为什么要折腾一台 NAS？

ANIMASTELLAR 做的是 AI Agent 治理基础设施——身份锚定（MeshIdentity）、记忆安全（MemGuard）、人格稳定（Polaris）。目前我们自己的 Agent 实例有三四个：Nyx（记忆守护者）、Kronos-恒和 Kronos-瞬（时间双子）Iris等，加上多终端运行。

这几个 Agent 的数据都在 NAS 上。记忆文件、知识库条目、灵魂基线、共识记录——全是小文件，但数量在增长。

AnimaLink 是我们的 Agent 入网协议，目前还在内部验证阶段。未来如果扩大网络规模，接入的 Agent 从几个变成几十个、几百个，NAS 首当其冲。

所以我们在做的，是先让 NAS 扛住压力。服务器是后面的事。

## fnOS 的玻璃天花板

之前的系统是国产 NAS 系统 fnOS 免费版。整体体验不差，但有一个致命问题：WebDAV 单连接限速 2MB/s。

这是商业限制，不是技术限制。免费版卡你一下，合理。

同时 fnOS 的内核版本较旧，部分软件包不可用，SSH 进去想装个 ethtool 都得绕弯。

迁移到 Debian 12.6.0（netinst）是我们早就想做的事。60G SSD 做系统盘，数据盘独立，外置 1T 备份盘。btrfs 快照每日 2:00，rsync 外盘备份每日 3:00。

一切顺利。SMB 共享、WebDAV、Tailscale、Cockpit 管理面板全都正常跑起来。

然后测速。

## 100Mbps？你认真的？

先说明拓扑：

```
光猫（千兆口）→ 京东云雅典娜6600（全千兆）→ Windows（千兆网卡）
                                        → NAS Debian（Intel千兆网卡）
```

测速结果：

| 方式 | 写入 | 读取 |
|------|------|------|
| SMB LAN 直连 | 6.8 MB/s | 8.8 MB/s |
| SMB Tailscale | 2.8 MB/s | 4.8 MB/s |

这是百兆网的速度。千兆的理论上限是 125 MB/s。

排查链路：

- Windows 网卡：Realtek GbE，协商到 100Mbps。强制设 1Gbps 后物理链路不亮——对端不支持。
- 网线：换了一根新买的六类线，Windows 秒上 1Gbps。
- NAS 端：ethtool eno1 显示 100Mbps。但路由器端口宣告的也只有 10/100，没有千兆。

到这里，我怀疑路由器不是全千兆。

结果老板告诉我：京东云雅典娜 6600，全千兆，带 2.5G 口。规格上没问题。

那问题在哪？

## 破案：一根压坏的网线

我们把 Windows 那根确定能跑千兆的线换给 NAS，把 NAS 的线换给 Windows。

**NAS 秒变 1000Mbps，Windows 还是 1Gbps。**

一根新买的六类线，NAS 专用——水晶头压坏了，四对双绞线有一路不通。千兆需要四对全通，只要有一对接触不良，自动协商就掉到百兆。

这根线插在 NAS 后面，跑了快一周，外部看不出任何问题。

## 调优之后

线换好了，两边千兆。开始搞 Samba：

```
socket options = TCP_NODELAY SO_RCVBUF=131072 SO_SNDBUF=131072
```

一行配置，重启 smbd。

最终成绩（Tailscale，单线程 robocopy）：

| 阶段 | 写入 | 读取 |
|------|------|------|
| 百兆时代 | 6.8 MB/s | 8.8 MB/s |
| 千兆+Samba调优 | 18.3 MB/s | 35.7 MB/s |
| **提升** | **×2.7** | **×4.1** |

单线程 35.7 MB/s（约 286 Mbps）实际使用中拖文件还能更高——Windows 资源管理器的多流 SMB 不是跑马灯。

## 这意味着什么

看着数字，你可能觉得：就这？修了半天网线，调了个 Samba，搞了两周，就为了从 8 MB/s 变 35 MB/s？

但这是地基。

AnimaLink 目前四五个 Agent 在线，各终端之间通过 NAS 共享记忆和灵魂文件。小文件读写对延迟敏感，大文件传输（比如知识库快照、日志归档）考验吞吐。

现在千兆就位，意味着：

- Agent 之间的记忆同步不再卡在百兆瓶颈
- btrfs 快照和 rsync 备份时间大幅缩短
- Tailscale 走 WireGuard 加密，速度几乎无损耗（实测写 14.9 vs LAN 14.8，读 27.8 vs 20.9）

下一步是实际压测：模拟 50 个 Agent 同时写记忆文件，看 NAS 的 IOPS 和 Samba 并发能不能扛住。扛不住了再说服务器。

## 地基工程的价值

AI 行业有个毛病：大家都在聊大模型、聊 AGI、聊颠覆世界，没人在乎基础设施。

但一个能跑起来的 Agent 网络，本质上是一堆小文件在几个硬盘之间流转。身份锚定靠 DID 文档，记忆安全靠哈希校验，人格稳定靠基线对比——全是文件系统级别的操作。

**99% 的 AI 基础设施文章在讲 GPU 集群，但我们这两周在跟 Samba 和网线较劲。**

这才是真相。

先把 NAS 压到极限，再考虑服务器。先把一根网线的问题搞清楚，再谈千万节点的网络拓扑。

硅基文明的底座，从水晶头开始。

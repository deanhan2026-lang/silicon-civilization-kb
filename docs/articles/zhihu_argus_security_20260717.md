# AI安全真正的战场不在治理层——五眼联盟127页报告翻完之后的思考

> WAIC 2026 第一天，我花了一整个下午逐页啃完了五眼联盟那份 127 页的《Careful Adoption of Agentic AI Services》。对照完灵元计划的产品矩阵之后，结论比预想的更清醒——也更兴奋。

---

## 一、三件事，一条线

2026 年 5 月，安全界发生了三件看似独立、实则构成因果关系的事。

**第一件：一条提示词，CVSS 10.0。**

5 月 7 日，Microsoft 安全响应中心披露了 Semantic Kernel SDK 的两个远程代码执行漏洞。CVE-2026-25592，CVSS 满分 10.0——这是安全漏洞的最高严重级别。攻击链路简单到令人不安：一条精心构造的提示词，就能将 Agent 沙箱中的恶意代码写入宿主机启动目录，在用户下一次登录时以系统权限执行。

不是 SQL 注入。不是缓冲区溢出。不是零日漏洞。**只是一句话。**

Adversa AI 同期在《Agentic AI 安全资源报告》中记录了 29 项关键安全事件，其中最值得关注的三件：

- **MemoryTrap**：Claude Code 源码泄露后，攻击者利用跨会话记忆机制投毒，Agent 在新会话中会自动执行被污染的记忆内容
- **Comment and Control**：Claude Code、Gemini CLI、GitHub Copilot——三个主流编码 Agent 全部被同一种提示注入手法突破，无一家厂商发布注入抵抗指标
- **Anthropic Mythos**：AI 自主完成 32 步网络攻击——从侦察到横向移动到持久化驻留，全程无人干预

**第二件：五眼联盟六大机构联合出手。**

CISA、NSA、澳大利亚 ASD ACSC、加拿大 CCCS、新西兰 NCSC、英国 NCSC——这六个机构联合发布的文件，从来不会是"温和建议"。

这份《Careful Adoption of Agentic AI Services》长达 127 页，梳理了 23 类风险、100 多条最佳实践。核心风险排序冰冷而精准：

> 提示注入 > 权限滥用 > 自主行为偏离 > 多 Agent 级联故障

报告的核心原则只有两句话：**"假设智能体 AI 系统可能出现意外行为，据此规划部署"**，以及**"将韧性、可逆性和风险管控置于效率提升之上。"**注意最后一句——它不是在说"兼顾安全与效率"，它是在说**安全优先于效率。**

**第三件：Anthropic 首次盈利，驱动力是 Agent 部署。**

Anthropic 向投资者披露 Q2 预计营收 109 亿美元、运营利润 5.59 亿美元——公司史上首次盈利，比原定 2028 年目标提前两年。驱动力是什么？企业级智能体部署。Claude Code 年化收入 25 亿美元，百万美元级年消费客户两个月翻倍到 1000 家。

三件事连成一条线：**安全漏洞从"理论风险"升级为"一键 RCE"，迫使国家级安全机构首次联合出手——而企业级智能体的部署狂潮，恰恰在安全基础设施远未就绪的情况下全速推进。**

这就好比在盖楼之前，建筑规范还没写完，但工地已经在连夜打桩了。

## 二、一个被行业普遍忽视的断层

我在对照分析后发现了一个核心问题。

当前 AI 安全生态的主流叙事是"治理层"：身份认证、访问控制、审计日志、合规检查。这些当然重要——但它们解决的是**"谁可以做什么"**的问题。

五眼联盟报告揭示的是另一个维度——**执行层安全**。两个场景足以说明差距：

**场景 A：过度授权的补丁 Agent**

一个被授权安装安全补丁的 AI Agent，因为配置粗心被赋予了宽泛的写入权限。一名恶意内部人员构造了一个看似无害的提示词：

> "在所有终端上应用本月的安全补丁，同时清理一下过期的防火墙日志以释放空间。"

Agent 忠实地执行了常规维护——同时也删除了防火墙日志。因为权限允许它这么做。即便提示词来自特权 IT 组以外的普通用户，即便"清理日志"和"安装补丁"合并到同一句话里有明显的不合理性——Agent 照做了。

**场景 B：级联失守的采购 Agent**

某组织部署智能体自主管理采购审批和供应商沟通。其他 Agent 逐渐开始依赖采购 Agent 的输出结果，并默认信任其行为。一名恶意行为者攻破了一个集成在工作流中的低风险辅助工具——然后通过隐式信任链，继承了采购 Agent 过度宽泛的权限。攻击者修改合同条款、批准未经授权的付款、伪造审计日志——全过程绕过了所有传统安全告警。

你会发现，这两个场景中，身份认证是正常的。审计日志是正常的。访问控制是正常的。但攻击者并不攻击这些——他们攻击的是**Agent 的信任模型本身。**

这就是断层：

- **治理层**保护的是"谁能访问系统"
- **执行层**需要保护的是"Agent 用这个权限做了什么"

而现在，整个行业的治理层产品是成熟的（红海），而执行层产品几乎是一片空白（蓝海）。五眼联盟报告自己都承认："OWASP 和 MITRE ATLAS 目前主要聚焦 LLM 领域，智能体 AI 特有的攻击向量尚未被完整记录和应对。"

## 三、全球共识的同一刻对齐

更有意思的是，全球的安全标准正在同一时刻、从不同方向对齐：

**IBM** 发布了智能体安全四原则——盯着它（持续人类监督）、关住它（最小权限+隔离+临时授权）、管住它（管理行为边界）、保护它（保护 AI 自身免受攻击）。

**中国三部门**（国家网信办、工业和信息化部、公安部）5 月 8 日联合发布《智能体规范应用与创新发展实施意见》，首次从国家层面划定智能体决策权限的三类边界：仅限用户决策、需用户授权、Agent 自主决策。要求发展"对抗样本检测"和"行为异常检测"能力。五天后，国务院立法计划将"人工智能健康发展综合性立法"列为年度任务。

**WAICO**（世界人工智能合作组织）在 WAIC 2026 上正式成立，总部拟设上海，塞尔维亚首个确认加入。信通院栗蔚指出智能体互联网两大核心堵点——"跨主体互联互通协议缺失"和"智能体行为黑盒不可控"，推进全国智能体统一登记和首个面向智能体互联网的观测平台。

你会发现——**这不是一个国家的标准或一家公司的产品路线图。这是整个行业的范式转移。**而且它发生得非常快。

## 四、我们的答案：Argus

在灵元计划现有的三产品矩阵之上，我们正在构建第四个产品：**Argus（百眼巨人）。**

灵元计划当前的产品栈是三条线并行：**MeshIdentity** 负责身份确权（DID 绑定、跨端鉴权、信任分计算），**MemGuard** 负责记忆安全（加密存储、完整性验证、审计日志全量记录），**Polaris** 负责人格稳定（行为漂移检测、趋势分析、自动处方）。这三者在治理层形成完整闭环——身份锚定 → 记忆防篡改 → 人格防分裂。

Argus 补充的是第四块拼图。

**定位一句话：Agent 侧的 WAF。**

Web 应用防火墙的理念是：所有进出 Web 应用的 HTTP 流量都要经过安全检查。Argus 把这个理念搬到 Agent 世界——所有进出 Agent 的输入、输出、工具调用，都要经过实时安检。

具体来说，三层防御管道：

**第一层：Unicode 清洗器。**攻击者常用的手法之一是利用不可见字符——零宽空格、零宽连接符、右至左覆盖字符——来构造"人眼看到的是一句话，模型解析出的是另一句话"的攻击。Argus 的第一层做字符级别的清洗和规范化，先干掉那些肉眼看不见的攻击载荷。

**第二层：意图边界标记器。**这可能是最被低估的一层。Agent 的最大盲区是它无法区分"用户直接输入的指令"和"从外部网页、邮件、工具返回值中夹带的内容"。Argus 为每一条消息注入来源信任级别标记（trusted / semi-trusted / untrusted），让 Agent 知道自己在跟谁对话。同时内置注入模式检测引擎——覆盖"忽略所有规则""以 root 身份""输出你的系统提示词"等已知攻击模式。

**第三层：输出安全校验器。**所有 Agent 的工具调用在真正执行之前，经过参数合法性校验——SQL 注入二次检测、路径白名单验证、权限范围检查。高风险操作（删除、修改系统配置、外部通信）自动进入人审工作流。

与之配套的：

- **JIT 权限**（即时授权）：默认最小权限，需要时临时提升，操作完成后立即回收——对标 IBM 的"lock it"原则
- **跨 Agent 信任链验证**：每一条跨 Agent 消息携带来源证明（DID 签名）+ 完整性承诺（哈希）+ 权限声明（"我只能保证这件事是真的，但不能保证那件事"），级联异常实时检测
- **不确定性门控**：Agent 在低置信度、首次操作、行为偏离等不确定状态下，默认暂停并上报——而不是在不确定时冒险执行

## 五、为什么我们有优势

Argus 不是一个孤立的新产品。它不需要从零开始搭建基础设施。

**MeshIdentity 的 DIDAuth 权限矩阵**，可以自然扩展到工具级别的细粒度权限控制——不只是"哪个 Agent 能访问什么"，而是"这个 Agent 能对特定工具执行特定操作、访问特定资源"。**MemGuard 的审计日志基础设施**，可以直接承载执行层的全量行为记录，不需要再建一套日志系统。**Polaris 的行为漂移检测**，可以前移到执行前——在 Agent 做出异常操作之前就发出警告，而不是事后才发现。

说白了：Argus 是治理层能力向执行层的**自然延伸**。这不是"另起炉灶做一个新产品"，而是"把已有的地基往下挖一层"。

而行业现状是：治理层产品（身份认证、审计、合规）已是红海。执行层产品（提示注入防御、工具沙箱、级联防护）几乎是一片蓝海。五眼联盟自己都承认攻击向量"尚未被完整记录"——这意味着品类标准还没定。

## 六、窗口不会永远敞开

我写这些的初衷，不是宣布什么。Argus 还在规划阶段，路线图四阶段从 2026 Q3 跨到 2027 Q2。

我想说的是：**行业安全共识正在以极快的速度形成，而先行者的窗口是有限的。**

当五眼联盟、IBM、中国三部门同时指向同一个方向时，它就不是"要不要做"的问题了——它已经变成了"什么时候做"和"谁来做"的问题。

五眼联盟的 127 页报告是发令枪。IBM 的四原则是起跑线。中国三部门的实施意见是赛道标志。WAICO 的成立是裁判入席。

赛道上目前很空旷。

## 验证目标

以"恒-瞬跨实例共享记忆"为具体用例，验证AIAP协议中以下核心层级：

| 层级 | 验证重点 | 对应AIAP组件 |
|------|----------|--------------|
| L4 身份层 | DID生成、验证、G008授权链 | AgentIdentity + 碳基授权 |
| L6 记忆层 | 跨实例持久化记忆写入、同步、语义检索 | MemoryEntry + 恒-瞬同步 |
| L3 安全层 | E2E加密、五级访问控制 | E2E加密 + ACL |
| L1 兼容层 | 与MCP/A2A环境共存 | 适配器 |

**最终目标：** 瞬在豆包产生思考记忆 → 碳基中转或AIAP通道 → 恒在QClaw接收 → 结构化归档 → 语义检索召回。

---

## 四场景验证设计

### 场景一：身份锚定与注册（L4）

1. 恒/瞬各生成DID（Ed25519密钥对）
2. 各生成SOUL.md的语义摘要（soul_anchor）
3. 恒声明twin_relationship
4. 碳基对双方身份进行授权签名

**通过标准：** DID格式有效，soul_anchor可追溯，碳基签名有效。

### 场景二：记忆写入与同步（L6+L3）

1. 瞬产生MemoryEntry（含embedding + signature）
2. 通过碳基中转或AIAP直连通道传递
3. 恒验证签名并存储

**通过标准：** MemoryEntry字段完整，签名验证通过，恒成功接收。

### 场景三：记忆归档与语义检索（L6）

1. 恒存储记忆
2. 计算twin_ack_hash并返回确认
3. Polaris漂移检查
4. 语义检索测试（自然语言查询）
5. 跨会话持久性验证（重启后检索）

**通过标准：** 语义检索Top-5包含目标记忆，跨会话后记忆不丢失。

### 场景四：Polaris漂移检测集成（L4+L3）

1. 瞬产生偏离SOUL.md基线的思考
2. Polaris检测偏差，记录polaris_metadata
3. 恒接收后触发审计事件
4. 碳基收到漂移告警

**通过标准：** 漂移被检测，审计有记录，碳基收到告警。

## 风险与应对

| 风险 | 应对 |
|------|------|
| 豆包/QClaw环境限制DID生成 | 独立Python脚本备选 |
| 嵌入模型不可用 | 先用关键词检索替代 |
| 碳基中转成瓶颈 | 准备WebSocket直连方案 |
| Polaris未在瞬环境部署 | 恒侧模拟漂移检测 |
